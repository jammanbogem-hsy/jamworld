# 에셋 공방·페이지·포털 디자인 규격

2026-10-20. Codex 디자인, Claude 앱 구현. 사용자 요청에 따른 확장 작업이며 구현 완료 기록이 아니다.

## 일관된 화면

기존 선명한 만화체 에셋과 어울리는 짙은 남색 외곽선, 큰 모서리, 코랄·금색·청록 강조색을 쓴다. 화면 전체를 장식하지 않고 주요 행동과 상태를 쉽게 구분한다. 낮은 해상도에서도 본문 16px, 버튼 44px 이상을 확보한다.

메인 이동은 ‘내 월드 / 에셋 공방 / 에셋 보관함’으로 구성한다. 교사에게만 ‘교사 검토’와 학급 관리가 보인다. 역할은 서버에서 결정하며 화면 토글로 권한을 바꾸지 않는다.

## 학생 공방

왼쪽은 에이전트 대화, 오른쪽은 제작 카드와 미리보기다. 작은 화면에서는 탭으로 나누며 대화 작성 내용은 유지한다.

1. 무엇을 만들지 대화하거나 그림을 첨부한다. 그림 없이 프롬프트만으로도 가능하다.
2. 제작 카드에 이름, 설명, 분류, 검색 태그, 시점, 기본 크기, 통과 가능 여부를 확인한다.
3. ‘선생님께 요청’으로 해당 제작안과 그림을 제출한다.
4. 승인 대기 중에는 이미지 생성 요청을 실행하지 않는다. 수정 후 제출하면 새 버전으로 검토받는다.
5. 교사가 승인하면 승인된 내용으로 생성한다. 생성 중인 상태와 오류·재시도 가능 여부를 표시한다.
6. 결과를 탑뷰/아이소 탭으로 확인한 뒤 ‘내 에셋에 저장’ 또는 ‘저장하지 않기’를 선택한다. 생성 완료와 보관함 저장은 다른 상태다.
7. 저장한 에셋은 편집기의 보관함 탭과 자연어 맵 제작에서 사용할 수 있다.

상태는 초안 / 승인 대기 / 반려 / 승인됨 / 생성 중 / 생성 완료 / 저장됨 / 생성 실패를 명확하게 표시한다. 제출 후 자동으로 새 요청을 만들거나 같은 생성 요청을 중복 실행하지 않는다.

## 교사 검토

검토 카드에 학생 별명, 제출 시간, 그림, 생성할 내용, 분류, 시점과 예상 생성 장수를 표시한다. ‘승인하고 생성’과 ‘반려하기’의 의미를 명확하게 한다. 반려 사유를 남기고 학생 화면에도 표시한다.

승인 시 프롬프트·그림·설정의 정확한 버전을 고정한다. 승인 후 학생이 내용이나 파일을 바꿔 승인 범위를 우회할 수 없어야 한다. 학급별 요청 목록과 상태 필터를 제공한다.

교사는 본인 학급을 관리하고, 학생은 본인의 요청·결과를 관리한다. 학급 공유 에셋은 같은 학급 구성원만 조회한다. 공개 Git 저장소에는 학생 그림이나 결과를 자동 업로드하지 않는다.

## 에셋 분류와 데이터

| 표시 | 내부 분류 | 기본 사용 |
|---|---|---|
| 바닥 | terrain | 이음매 없는 바닥 텍스처, 걷기 가능 |
| 자연 | nature | 나무·바위·덤불·꽃 |
| 건물·벽 | building | 집·벽·문·울타리 |
| 가구 | furniture | 책상·의자·책장 |
| 상호작용 | interactive | 포털·안내판·퀴즈 표시물 |
| 장식 | decor | 깃발·화분·조명 |
| 인물 | character | 배치용 인물과 플레이어 아바타를 구분 |

태그는 검색 가능한 짧은 단어 1~8개다. 에이전트가 제안하고 학생·교사가 확인한다. 기본 충돌 여부, 논리 크기, 그림 기준점, 시점별 이미지, 제작자·요청 버전·원본 출처를 보관한다.

한 장짜리 배치용 인물을 걷기 아바타로 표시하지 않는다. 플레이어 아바타는 방향·걷기 프레임 규격을 충족해야 선택할 수 있다. 상호작용 그림을 생성했다고 실제 포털이나 퀴즈 기능이 자동 생기는 것처럼 표시하지 않고 사용할 동작을 별도로 지정한다.

바닥은 불투명한 정사각 텍스처로 만들고 투영 행렬로 두 시점에 적용한다. 나머지는 동일한 물체를 탑뷰와 아이소로 각각 생성한다. 기존 이미지와 다른 시점의 그림을 섞지 않는다.

## 포털 연결

첫 클릭 후 시작 포털을 맵에 분명히 표시하고 ‘시작’ 배지를 붙인다. 아직 확정되지 않은 쌍임을 점선 테두리로 표시한다. 커서까지 연결선을 그리며 도착 위치 미리보기를 보여 준다.

상단 안내: ‘시작 포털을 설치했어요. 도착 페이지와 위치를 선택하세요.’ 도착 페이지 선택, 시작 위치로 돌아가기, 취소를 제공한다.

다른 페이지로 넘어가도 출발 페이지 이름과 좌표를 안내 카드에 남긴다. 도착을 클릭하면 양방향 쌍을 한 번에 확정한다. 취소·Esc·도구 변경 시 임시 포털은 제거한다. 실행 취소/다시 실행은 양쪽 페이지를 함께 처리한다.

## 배치 크기

배치 전 도구와 선택 속성에서 배율을 조절한다. 0.5~3배 범위, 1배 복원 버튼, 실제 차지하는 칸 수를 표시한다. 그림만 커지고 충돌은 작게 남는 상태를 피한다. 사용할 수 없는 배치는 미리보기와 사유로 알려 준다.

## 맵 페이지

하단에 페이지 탭을 둔다. 추가·이름 변경·복제·순서 변경을 제공하고 프로젝트의 기존 맵 목록과 같은 데이터를 사용한다. 기존 맵을 새 문서로 덮어쓰지 않는다. 포털 속성에서 도착 페이지·위치를 확인하고 수정한다.

## 이식과 성능

논리 맵, 에셋 메타데이터, 서버 기록, 이미지 파일의 저장 경계를 구분한다. 원본 PNG/생성 프롬프트와 실행용 WebP/프레임 좌표를 보존한다. 자체 호스팅으로 옮길 때 API 키와 DB·파일 저장소를 별도 이관할 수 있도록 문서화한다.

현재 페이지와 필요한 시점의 에셋만 읽고 이미지 캐시에 상한을 둔다. 학생 그림이나 고해상도 생성 결과를 전체 목록에서 한꺼번에 디코드하지 않는다. 생성 중 UI는 폴링 빈도를 제한하고 탭이 숨겨지면 중지한다.

실제 크롬북 성능 검증은 아직 남아 있다.

## 후속 확장: 동작을 포함한 건물

사용자가 추가로 확인한 방향이다. 아래는 설계이며 아직 구현·검증 완료가 아니다.

‘문이 열리고 계단으로 오르내리는 2층집’은 그림 한 장 대신 재사용 가능한 건물 묶음으로 생성한다. 외관 이미지, 층별 공간, 충돌 영역, 문 상태, 입구·계단 연결과 실내 영역을 함께 저장한다. 다른 맵에 배치할 때 내부 식별자를 새로 만들고 연결도 함께 갱신한다.

동작은 검증된 모듈을 선언형 데이터로 조합한다. 문 열기/닫기, 공간·층 이동, 안내, 퀴즈부터 지원하며 새 동작은 구현·검증 후 카탈로그에 추가한다. 에이전트가 임의 코드를 생성해 사용자 브라우저에서 즉시 실행하는 구조로 만들지 않는다.

교사 승인 화면에는 ‘생성 그림’과 ‘포함 동작’을 모두 표시한다. 미리보기에서 문 열기와 계단 왕복을 직접 확인한 뒤 저장할 수 있어야 한다. 이미지 생성 완료를 동작 검증 완료로 표시하지 않는다.

건물 내부 표현에는 두 방식이 있다.

- **페이지 연결:** 외관의 입구에서 실내 페이지로 이동하고, 계단에서 다음 층 페이지로 이동한다.
- **같은 맵의 실내:** 바닥·벽·지붕·문·실내 가구를 별도 레이어로 구성한다. 캐릭터가 실내 영역에 들어가면 지붕과 캐릭터를 가리는 앞벽을 숨기거나 반투명하게 한다. 위층은 숨기고 현재 층을 보인다. 밖으로 나가면 외관을 복원한다.

같은 맵 방식은 지붕이 포함된 단일 PNG 전체를 흐리게 하는 것으로 대체하지 않는다. 지붕 아래 바닥과 가구가 실제로 존재해야 한다. 투명해진 벽의 충돌은 유지하고, 문을 열 때만 해당 통행 영역을 변경한다. 실시간 3D 조명 대신 2D 레이어·영역 판정·짧은 투명도 전환을 사용해 기존 저전력 렌더링 구조를 유지한다.
